# Поставка фичи

Учитывать project rules качества / Excel / тестов. Не копировать чеклисты сюда целиком.

## Общий порядок

1. Опереться на существующие аналоги в репо (не параллельный стиль).
2. Крупное — этапами с видимым прогрессом (todos).
3. Harden по правилу качества: тесты, exceptions, структура, нейминг, summary — без отдельной просьбы.
4. В конце: кратко статус + что осталось / вне объёма.

## Режим: старт («начни», «реализуй», «реализуй план»)

- Сразу писать код по плану/ТЗ; не подменять работу повторным планом, если план уже есть.
- Алгоритмическая фича — тесты в том же цикле поставки, не «потом если попросят».
- MVP по сроку — явно фиксировать, что отложено.

## Режим: продолжение («продолжай», «дальше», «продолжи»)

- Не начинать анализ и архитектуру с нуля.
- Восстановить контекст: todos, незакрытые файлы фичи, последний этап; при новом чате — по git/файлам фичи.
- Сделать следующий осмысленный кусок; в конце — короткий остаток.
- Не превращать «продолжай» в ревью, пока пользователь сам не попросит анализ/ревью.
