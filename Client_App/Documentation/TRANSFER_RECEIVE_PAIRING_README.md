# Проверка операций приёма-передачи

## Назначение

Функция находит операции передачи и приёма, для которых не нашлась парная операция у контрагента, и выгружает их в Excel.

**Текущая реализация:** формы **1.1**–**1.5**, режимы **выбранная организация** и **вся БД**. Листы 1.6–1.8 — пустые заглушки. Сверка same-form (1.1↔1.1 … 1.5↔1.5).

## Где вызывается

- **Аналитика** → **Выбранная организация** → **«Проверка операций приёма-передачи»**
- **Аналитика** → **«Проверка операций приёма-передачи (вся БД)»** (`CommandParameter="All"`)
- **Контекстное меню организации** (ПКМ, вкладка «Формы 1») → **Аналитика** → пункт выбранной org

## Параметры сопоставления

Перед выгрузкой открывается диалог с чекбоксами полей **отдельно для каждой формы** (сетка **4×2**: 1.1–1.4 / 1.5–1.8; заполнены **1.1–1.5**, 1.6–1.8 — заглушки). Снятое поле не участвует в решении «парная / непарная» и не подсвечивается.

**Не участвуют в сравнении** (только вывод): рег.№, ОКПО организации, сокращённое наименование, даты периода, № п/п.

## Excel

- Лист **«Легенда»** (цвета, % и типичные жёлтые случаи: ведущие нули, перестановка знаков, хвост даты у номера, скобки у типа, **диапазон зав.№**).
- Листы **«Форма 1.1»** … **«Форма 1.5»**: слева непарная операция, справа после тёмного разделителя — ближайшее совпадение; **зелёный / жёлтый / красный**; колонка **«Схожесть, %»**.
- На 1.2: наименование → зав.№ → масса → … → тип УКТ → номер УКТ.
- На 1.5: как 1.1 без ОКПО изготовителя.
- Имя файла (org): `{рег}_{ОКПО}_проверка_приёма_передачи`.
- Имя файла (вся БД): `проверка_приёма_передачи_вся_БД`.

### Closest-match (soft-score)

Парность **не** менялась: для пары по-прежнему нужны точные ключи. Soft-score только выбирает и подсвечивает кандидата справа. Общие правила — `ExcelExport/Pairing/Shared` (с проверкой по коду 41).

| Сигнал | Роль |
|--------|------|
| Паспорт + зав.№ | Самый сильный вес; полное совпадение обоих (непустых) — бонус |
| Зав.№ `рег/год/номер` ↔ ядро | Near, ядро совпадает с последним сегментом полного номера |
| Зав.№ диапазон / список с префиксом «номера» ↔ одиночный (qty = N) | Near у зав.№ и количества (не паспорт) |
| Ведущие нули / перестановка соседних знаков / хвост даты у номера | Near (паспорт, зав.№, УКТ) |
| Тип с уточнением в скобках | Near |
| ОКПО кол.19 (на 1.5 — кол.15): `8 цифр` ↔ голова `8_5` | Пара принимается; closest — Near (~0.99) |
| ОКПО кол.19: длинный номер с несколькими опечатками в цифрах | Closest — Near; короткие (~8) так не смягчаются |
| Суффикс года паспорта при **том же ядре** | Near; разные ядра при общем годе — Mismatch |
| Lookalike в типе/номере | Визуально похожие символы (цифра ↔ буква и т.п.) |
| Пустые серии: `-`, `б.н.`, `н.д.`/`н/д`, `нет данных`, … | Как пустой номер; qty-drain на 1.1/1.5 |
| Активность | ±10%; парсинг через `FormExponentialEquality` (десятичная и экспоненциальная запись) |
| Радионуклиды | Порядок не важен; отсутствие нуклида — Mismatch |
| Опечатка в 1 символ (длина > 2) | Near; 2+ символа — Mismatch |

Цвета: Exact → зелёный, Near → жёлтый, Mismatch → красный. **«Схожесть, %»**: ≥80 / 50–79 / &lt;50. Подробности — лист «Легенда».

## Архитектура (org / вся БД)

Алгоритм парности и closest-match — **одно ядро** (`AnalyzeFormForOrganization` / `ComputeUnpairedOperations` / `BuildClosestMatchResults`): без обращений к БД, только DTO. Каждая включённая форма вызывает его со своими `TransferReceiveFormParams` и отдельным пулом ops.

Формы подключены через **реестр** `ImplementedFormDescriptors` (`Forms.cs`): load / Excel / closest идут циклом по включённым формам (`EnabledForms`).

| Режим | Отличие |
|-------|---------|
| Выбранная org | Точечная загрузка своих ops по включённым формам + контрагентов по ОКПО кол. 19 (пакеты по **20 org**, строки keyset-страницами по **2500**); при галочке ОКПО — SQL-фильтр кол.19; своя org в пул не перечитывается |
| Вся БД | **Один scan ops** на форму keyset-страницами по **5000** → активные org + титулы (в т.ч. контрагенты с ops) → ОКПО-карта из титулов (+ хвост `LoadRepsIdsByOkpo`) → **один** shared `opsByOrgOkpo` и **общие** индексы pairing/closest/norms на форму → цикл unpaired/closest/Excel без пересборки индексов |

Копия temp DB не оптимизируется (общая для выгрузок, доля времени мала).

### Как добавить форму (напр. 1.6+)

1. `TransferReceiveFormId` + строка в `ImplementedFormDescriptors` (SheetName, layout).
2. Слот в `TransferReceiveParamsSet.Create(...)` / чекбоксы диалога.
3. Ветки в диспетчерах: `LoadFormOpsForRepsAsync` / `…ForRepsIdsAsync` / `LoadFormOpsPagedWholeDbAsync`.
4. При отличии колонок/soft — layout writer и поля в `TransferReceiveFormParams`.
5. Тесты + легенда.

### Smoke вручную

- Выбранная org с известными парами на **1.1–1.5** → пустой или ожидаемый Excel.
- Вся БД: несколько org с непарными → один файл, append; этапы загрузки **1.1…1.5**.
- Снятие Check* в диалоге меняет состав непарных; **все поля формы выкл.** → форма не грузится и не пишется в Excel.
- Дата ±1 день → строка в отчёте, дата **жёлтая** у closest (окно ±15).
- Soft: зав.№ с префиксом рег./года, диапазон зав.№↔одиночный номер, УКТ-варианты, активность на порядок — жёлтый; колонка «Схожесть, %».
- Форма 1.2: масса ±10% / kg↔т жёлтый; PackType; наименование.
- Форма 1.3: разное агрегатное состояние → непарная; снятие CheckAggregateState → пара.
- Форма 1.4: вид / объём ±10% / дата изм. активности exact; масса и агр. состояние.
- Форма 1.5: 26↔36; лист без ОКПО изготовителя; qty-drain на «н.д.»; `1000`↔`1e+3`.
