# Проверка парности операций при переводе РВ → РАО (код операции 41)

## Назначение

В программе предусмотрен перевод сведений о **радиоактивных веществах (РВ)** в сведения о **радиоактивных отходах (РАО)** по **коду операции 41**. Перевод выполняется из форм учёта РВ в соответствующие формы учёта РАО. На практике часть источников после перевода «теряется»: запись есть только в форме РВ или только в форме РАО, либо данные в парных строках не сходятся.

**Функция поиска непарных строк** автоматически находит такие расхождения и выгружает их в Excel. Это помогает:

- выявить **потерянные при переводе** источники и операции;
- понять, **где именно** осталась «лишняя» или **отсутствующая** запись;
- опираясь на даты операций и документов в выгрузке, **восстановить хронологию** передвижения источников между формами и отчётными периодами;
- провести сверку **по выбранной организации**.

Функция **не заменяет** кнопку перевода по коду 41 и **не исправляет** данные сама — она даёт наглядный отчёт для ручного анализа и доработки отчётности.

---

## Связь форм РВ и РАО

| Форма РВ (источник) | Форма РАО (приёмник) | Содержание |
|---------------------|----------------------|------------|
| **1.1** — ЗРИ | **1.5** — РАО в виде отработавших ЗРИ | закрытые источники |
| **1.2** — изделия из обеднённого урана | **1.6** — некондиционированные РАО | ИОУ |
| **1.3** — ОРИ (отдельные изделия) | **1.6** | открытые источники — изделия |
| **1.4** — ОРИ (прочие) | **1.6** | открытые источники — иные учётные единицы |

**Текущая реализация:** одна команда выгрузки непарных операций 41 по **выбранной организации** сразу по всем четырём направлениям (листы Excel для форм **1.1–1.6**). Перед выгрузкой открывается диалог параметров сопоставления (чекбоксы полей для каждой пары форм).

> Режим проверки **по всей базе данных** в этом релизе **не реализован** (команда доступна только при выбранной организации).

---

## Где вызывается

- **Аналитика** (меню главного окна) — пункт **«Непарные операции 41 (формы 1.1–1.6)»**.
- **Контекстное меню организации** (ПКМ по строке в списке организаций) — **Аналитика** → тот же пункт.

Нужно, чтобы в списке была **выбрана** организация. Без выбора команда недоступна.

## Как работает проверка

### 1. Параметры сопоставления

В диалоге пользователь выбирает, **какие поля** участвуют в ключе для каждой пары (1.1↔1.5, 1.2↔1.6, 1.3↔1.6, 1.4↔1.6). По умолчанию включены все поля пары. Снятие чекбокса исключает поле из сравнения (удобно, если расхождение по одному реквизиту не должно давать «непарную»).

### 2. Отбор операций

Из временной копии БД выбираются строки с **кодом операции 41** в формах 1.1–1.6 **только выбранной организации**. Сначала читаются поля, нужные для сравнения; полные строки подгружаются позже только для непарных Id.

### 3. Сопоставление

| Направление | Что сравнивается (при включённых чекбоксах) | Числовой допуск |
|-------------|---------------------------------------------|-----------------|
| **1.1 ↔ 1.5** | дата операции; паспорт; тип; радионуклиды; зав.№; активность; количество; дата выпуска; документ (вид/номер/дата); ОКПО поставщика/получателя и перевозчика; упаковка (имя/тип/номер) | активность ±10% |
| **1.2 ↔ 1.6** | дата операции; масса (в тоннах); β- и α-активности (из массы, как при переводе); дата измерения активности (= дата операции на 1.2); документ; упаковка | масса и активности ±10% |
| **1.3 ↔ 1.6** | дата операции; основные радионуклиды; 4 вида активностей; дата измерения (= дата выпуска на 1.3); документ; упаковка. Поле **Type** формы 1.3 **не** сравнивается | активности ±10% |
| **1.4 ↔ 1.6** | дата операции; объём; масса (т); основные радионуклиды; 4 вида активностей; дата измерения; документ; упаковка | объём, масса, активности ±10% |

На стороне **1.6** пара ищется среди 1.2, затем 1.3, затем 1.4 (**приоритет 12→13→14**) теми же предикатами, что и при сверке РВ→РАО.

**Нормализация** (как в аналитике СНК): регистр, лишние пробелы/спецсимволы, lookalike RU/EN, ведущие нули; для радионуклидов — порядок в списке; для дат — канонический формат.

**Особый случай 1.1↔1.5 — пустые паспорт и заводской номер.**  
Партия может быть внесена как одна строка с количеством 8 или как восемь строк с количеством 1. При совпадении остальных ключевых полей сравнивается **суммарное количество**; в отчёт попадает только нераспределённый остаток.

**Не сравнивается** (поля РАО после перевода / для пользователя): код РАО, статус РАО, ОКПО приёмника на 1.6 (берётся с организации при переводе), subsidy / refine / FCP и т.п. Они могут выводиться в Excel, но на признак «парная / непарная» не влияют.

### 4. Closest-match и подсветка

Для каждой непарной строки подбирается **ближайший** кандидат на другой стороне (максимум совпавших включённых полей). В Excel совпавшие/несовпавшие ячейки **подсвечиваются**, чтобы быстрее увидеть причину расхождения. Для листа 1.6 выбирается лучший профиль среди 1.2 / 1.3 / 1.4 (при равном счёте — приоритет 1.2).

### 5. Результат и Excel

- Непарные на стороне РВ и на стороне РАО попадают в выгрузку.  
- Если непарных нет — показывается уведомление, файл не формируется.  
- Файл **.xlsx**: отдельные листы **«Форма 1.1» … «Форма 1.6»**, реквизиты организации и периода, таблица с фильтром.  
- Имя файла обычно включает рег. №, ОКПО и пометку о непарных 41; при совпадении имени — суффикс `_1`, `_2`, …

Для расчёта активностей 1.3/1.4 при выгрузке нужен справочник **`data\Spravochniki\R.xlsx`**. Если файл отсутствует или занят — команда сообщает об ошибке и прерывается.

## Чем помогает на практике

| Задача | Как помогает |
|--------|----------------|
| Найти источник, который не перевели в РАО | Непарная строка на 1.1–1.4 |
| Найти «лишнюю» запись в РАО | Непарная строка на 1.5/1.6 |
| Массовый перевод без серийных номеров | Сумма количества при пустых паспорт/зав.№ (1.1↔1.5) |
| Сверка перед сдачей | Режим «выбранная организация» |
| Увидеть, *чем* строки почти совпали | Подсветка closest-match |
| Восстановить хронологию | Даты операции, выпуска и документов в выгрузке |

После исправления данных имеет смысл **повторно** запустить проверку или выполнить штатный **перевод по коду 41**.

---

## Рекомендации пользователю

1. Перед проверкой завершите ввод операций 41 в формах РВ и перевод там, где он требуется.  
2. Непарная строка — повод открыть отчёт и сравнить с парной формой, а не автоматический признак ошибки ввода.  
3. При пустых паспорте и заводском номере сверяйте **суммарное количество** по группе, а не только число строк.  
4. Если ложные «непарные» из‑за одного поля — снимите соответствующий чекбокс в диалоге параметров.  
5. Закройте `R.xlsx`, если он открыт в Excel, перед выгрузкой с формами 1.3/1.4.

## Ручной smoke-чеклист перед релизом

1. Организация выбрана → диалог параметров → Excel с **шестью** листами (1.1–1.6).  
2. После штатного перевода 41 идеальная пара → сообщение, что непарных нет.  
3. Расхождение документа или массы → непарные с обеих сторон + **подсветка** ячеек.  
4. Снять чекбокс расходящегося поля → строки склеиваются в пару.  
5. Отмена в диалоге сохранения файла → без падения, прогрессбар закрывается.  
6. Нет или locked `R.xlsx` → понятное сообщение об ошибке (сценарий с 1.3/1.4).

## Вне объёма этого релиза (техдолг)

- Выгрузка / сверка **по всей БД** (`repsId: null`; при multi-org нужно отдельно заполнять `RepsId` через `ReportId` — Firebird не поддерживает APPLY с корреляцией `reps.Id` в SELECT).  
- Отдельные unit-тесты генерации активностей по fixture `R.xlsx` и автоsmoke номеров колонок Excel.  
- E2E «кнопка перевода → парность пустая».
