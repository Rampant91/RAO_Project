# Правила и сценарии для агента (RAO_Project)

Шпаргалка для разработчика. Агенту коды не нужны — пишите обычным текстом; нужное подхватывается по always/glob/description.

## Я пишу → агент делает

| Формулировка | Ожидание | Skill |
|--------------|----------|--------|
| Составь план / Plan mode | План работ, MVP vs полный объём | — |
| Продумай реализацию (Ask) | Дизайн по коду репо, без правок | — |
| Начни реализацию / реализуй / реализуй план | Код по плану; качество и тесты сразу | `postavka-fichi` |
| Продолжай / дальше | Следующий этап, без нового большого плана | `postavka-fichi` |
| Проанализируй сделанное и поправь критическое | Аудит → только critical fixes | `review-k-relizu` |
| Ревью перед релизом / готовы к релизу? | Вердикт + приоритеты; правки — если просили | `review-k-relizu` |
| Ещё раз финальное ревью всех изменений | Короткий повторный вердикт по актуальному diff | `review-k-relizu` |

## Rules (требования)

| Файл | Когда включается |
|------|------------------|
| `rules/kachestvo-fichi.mdc` | **Всегда** — бар качества |
| `rules/excel-export.mdc` | `ExcelExport/` — общее + блок только для compare |
| `rules/testy-algoritmov.mdc` | Тесты алгоритмов (Pairing/TR/FormPrintCompare/Snk/…) |
| `rules/avalonia-ui.mdc` | Views / axaml / Behaviors — Avalonia **0.10.22** |
| `rules/firebird-db.mdc` | ExcelExport + repository/query-код — лимит Firebird `IN` ~1500 |
| `rules/database-migrations.mdc` | `*.cs` — Migrate только через обёртку |

## Skills (процессы)

| Skill | Когда |
|-------|--------|
| `skills/postavka-fichi/` | Старт и продолжение реализации фичи |
| `skills/review-k-relizu/` | Critical / release / final ревью |

## Принципы

- Один always-чеклист качества; остальное — узкие glob-rules
- В skills — режимы и порядок, не копия чеклиста
- Rules не обновлять по ходу фичи; править по явной просьбе или когда одна формулировка повторяется 2–3 раза
- Не дублировать то же в глобальных User Rules Cursor
