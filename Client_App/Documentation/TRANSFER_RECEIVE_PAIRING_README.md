# Проверка операций приёма-передачи

## Назначение

Функция находит операции передачи и приёма, для которых не нашлась парная операция у контрагента, и выгружает их в Excel.

**Текущая реализация:** формы **1.1**, **1.2**, **1.3** и **1.4**, режимы **выбранная организация** и **вся БД**. Листы 1.5–1.8 создаются пустыми (зарезервированы). Сверка только same-form (1.1↔1.1 … 1.4↔1.4).

## Где вызывается

- **Аналитика** → **Выбранная организация** → **«Проверка операций приёма-передачи»**
- **Аналитика** → **«Проверка операций приёма-передачи (вся БД)»** (`CommandParameter="All"`)
- **Контекстное меню организации** (ПКМ, вкладка «Формы 1») → **Аналитика** → пункт выбранной org

## Параметры сопоставления

Перед выгрузкой открывается диалог с чекбоксами полей **отдельно для каждой формы** (сетка **4×2**: 1.1–1.4 / 1.5–1.8; заполнены 1.1–1.4, остальные — заглушки). Снятое поле не участвует в решении «парная / непарная» и не подсвечивается.

**Не участвуют в сравнении** (только вывод): рег.№, ОКПО организации, сокращённое наименование, даты периода, № п/п.

## Excel

- Лист **«Легенда»**.
- Листы **«Форма 1.1»** / **«Форма 1.2»** / **«Форма 1.3»**: слева непарная операция, справа после тёмного разделителя — ближайшее совпадение с теми же колонками; **зелёный / жёлтый / красный** по уровню поля; колонка **«Схожесть, %»** (жирным).
- На 1.2: наименование → зав.№ → масса → … → тип УКТ → номер УКТ (порядок как в форме, без пустых колонок).
- На 1.1/1.3: тип УКТ не выгружается (не участвует в сверке); на 1.3 агрегатное состояние — сразу после даты выпуска (как в форме).
- На 1.3 колонка «Количество, шт» заменена на **«Агрегатное состояние»**.
- Имя файла (org): `{рег}_{ОКПО}_проверка_приёма_передачи`.
- Имя файла (вся БД): `проверка_приёма_передачи_вся_БД`.

### Closest-match (soft-score)

Парность **не** менялась: для пары по-прежнему нужны точные ключи (дата операции, парные коды, паспорт/зав.№ и т.д. по галочкам). Soft-score только выбирает и подсвечивает кандидата справа.

| Сигнал | Роль |
|--------|------|
| Паспорт + зав.№ | Самый сильный вес; полное совпадение обоих (непустых) — бонус |
| Зав.№ `рег/год/номер` ↔ ядро | Почти Exact (жёлтый Near), напр. `74041/22/0436` ↔ `0436` |
| ОКПО кол.19: `8 цифр` ↔ голова `8_5` | Пара принимается; closest — жёлтый Near (~0.99) |
| Суффикс года паспорта при **том же ядре** | Near (`3197/25` ↔ `3197/2`); разные ядра при общем годе (`829/22`↔`721/22`) — Mismatch |
| Lookalike в типе/номере | `3C0`=`3СО`=`ЗС0`; `4С0`↔`4СО-534` — Near |
| Радионуклиды | Порядок не важен; отсутствие/лишний нуклид — Mismatch (вес повышен) |
| Опечатка в 1 символ (длина > 2) | Near; 2+ символа — Mismatch |

Цвета: Exact → зелёный, Near → жёлтый, Mismatch → красный. **«Схожесть, %»** — нормированный индекс (не калиброванная вероятность): ≥80 / 50–79 / &lt;50 с той же палитрой. Подробности — лист «Легенда».

## Архитектура (org / вся БД)

Алгоритм парности и closest-match — **одно ядро** (`AnalyzeFormForOrganization` / `ComputeUnpairedOperations` / `BuildClosestMatchResults`): без обращений к БД, только DTO. Каждая включённая форма вызывает его со своими `TransferReceiveFormParams` и отдельным пулом ops.

Формы подключены через **реестр** `ImplementedFormDescriptors` (`Forms.cs`): load / Excel / closest идут циклом по включённым формам (`EnabledForms`).

| Режим | Отличие |
|-------|---------|
| Выбранная org | Точечная загрузка своих ops по включённым формам + контрагентов по ОКПО кол. 19 (пакеты по 20 org); при галочке ОКПО — SQL-фильтр кол.19; своя org в пул не перечитывается |
| Вся БД | **Один scan ops** на форму → активные org + титулы (в т.ч. контрагенты с ops) → ОКПО-карта из титулов (+ хвост `LoadRepsIdsByOkpo`) → **один** shared `opsByOrgOkpo` и **общие** индексы pairing/closest/norms на форму → цикл unpaired/closest/Excel без пересборки индексов |

Копия temp DB не оптимизируется (общая для выгрузок, доля времени мала).

### Как добавить форму (напр. 1.5+)

1. `TransferReceiveFormId` + строка в `ImplementedFormDescriptors` (SheetName, layout).
2. Слот в `TransferReceiveParamsSet.Create(...)` / чекбоксы диалога.
3. Ветки в диспетчерах: `LoadFormOpsForRepsAsync` / `…ForRepsIdsAsync` / `LoadFormOpsPagedWholeDbAsync`.
4. При отличии колонок/soft — layout writer и поля в `TransferReceiveFormParams`.
5. Тесты + легенда.

### Smoke вручную

- Выбранная org с известными парами 21↔31 на **1.1 / 1.2 / 1.3 / 1.4** → пустой или ожидаемый Excel.
- Вся БД: несколько org с непарными → один файл, строки append без перезаписи; progress «Организация i из N»; этапы «загрузка формы 1.1…1.4» → пулы/индексы → цикл org.
- Снятие Check* в диалоге (секции 1.1–1.4) меняет состав непарных; **все поля формы выкл.** → форма не грузится и не пишется в Excel.
- Дата ±1 день → строка в отчёте, дата **жёлтая** у closest (окно ±15).
- Soft: зав.№ с префиксом рег./года, УКТ-варианты, активность на порядок — жёлтый; колонка «Схожесть, %».
- Форма 1.2: масса ±10% / kg↔т жёлтый; PackType; наименование.
- Форма 1.3: разное агрегатное состояние → непарная; снятие CheckAggregateState → пара.
- Форма 1.4: вид / объём ±10% / дата изм. активности exact; масса и агр. состояние.
