# Ревью к релизу

Учитывать правило качества фичи. Чеклист не раздувать повторами.

## Общий чеклист аудита

1. Логика и краевые случаи  
2. Тесты: дыры, дубли, лишнее  
3. Exceptions / ресурсы / temp; массовые `IN`/Contains под Firebird (~1500)  
4. Структура, нейминг, regions/summary  
5. UX результата (для compare-Excel — легенда, сводка, подписи)  
6. README/smoke при нетривиальной команде  
7. Риски Shared/Comparers для соседних команд  

## Режим: critical («проанализируй и поправь критическое», «исправь важное»)

1. Найти блокеры: неверная логика, exceptions, порча данных, сломанный UX вывода, красная сборка/тесты.
2. Исправить **только** их.
3. Без cosmetic/refactor «заодно», кроме необходимого для фикса.
4. Кратко: что было критично и что сделано.

## Режим: release («ревью перед релизом», «готовы к релизу», «что доделать»)

1. Пройти чеклист аудита.
2. Вердикт: **готово** / **почти** / **не готово** + приоритетный список.
3. Код менять только если пользователь просит исправить; иначе — план действий.

## Режим: final («ещё раз», «финальное ревью», «все изменения»)

1. Смотреть актуальное состояние / diff целиком; не копировать предыдущий отчёт.
2. Акцент: что изменилось с прошлого ревью, новые риски, остались ли блокеры.
3. Короткий итог: **ship** / **ship after N fixes** / **не ship**.
