# Конвертер выгрузки всех форм → .RAODB

## Назначение

Обратная операция к аналитической выгрузке форм (**Аналитика → … → Форма X.Y**).

Вход: `.xlsx` с листами `Отчеты X.Y` (и опционально `Примечания X.Y`).  
Выход: отдельные `.RAODB` (по одному на группу строк-отчёт).

Меню: **Дополнительно → Конвертер выгрузки всех форм в .RAODB** (режим разработчика).

Форма определяется автоматически по имени листа и/или эталону заголовков колонок; перед записью показывается список распознанных листов.

## Поддержка форм

- **1.1–1.9** (Master 1.0, ключ по периоду)
- **2.1–2.12** (Master 2.0, ключ по отчётному году)

## Важно

- Титул организации (форма **1.0** / далее **2.0**) читается из **текущей** (активной) БД по паре рег.№ + ОКПО — без полной временной копии `.RAODB`. В Excel этих полей нет.
- В `.RAODB` Master всегда содержит **ровно 2** строки Form 1.0 (`NumberInOrder` 1 и 2).
  В части исходных БД у Master бывают **лишние** строки `form_10` с тем же `NumberInOrder`
  (две пары 1+2 с разными `Id`): UI формы 1.0 биндит только `[0]`/`[1]`, поэтому после
  сортировки по Order данные юрлица могут оказаться в блоке обособленного. Конвертер
  выбирает по одной строке на order (наиболее заполненная; при ничьей — меньший `Id`),
  слоты независимы; исходную БД не изменяет.
- Колонка `ID` игнорируется.
- Сокращённое наименование из Excel не подставляется в Master.
- Исполнитель отчёта в аналитической выгрузке отсутствует — в `.RAODB` поля исполнителя пустые.
- Активная БД не изменяется.
- Это **не** тот же конвертер, что «Конвертер из Excel в .RAODB» (печатный layout).

## Ключ группировки

- **1.x:** `(Рег.№, ОКПО, дата начала, дата конца, номер корректировки)`
- **2.x:** `(Рег.№, ОКПО, отчётный год, номер корректировки)`

## Заголовки

Эталон колонок должен совпадать с `ExcelExportBaseAllAsyncCommand.FillHeaders("X.Y")`.  
При изменении выгрузки обновить соответствующий `FormsExcelExportHeaders*`.
