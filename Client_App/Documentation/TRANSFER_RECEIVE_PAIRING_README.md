# Проверка операций приёма-передачи

## Назначение

Функция находит операции передачи и приёма, для которых не нашлась парная операция у контрагента, и выгружает их в Excel.

**Текущая реализация:** формы **1.1** и **1.3**, режимы **выбранная организация** и **вся БД**. Листы 1.2, 1.4–1.8 создаются пустыми (зарезервированы). Сверка только same-form (1.1↔1.1, 1.3↔1.3).

## Где вызывается

- **Аналитика** → **Выбранная организация** → **«Проверка операций приёма-передачи»**
- **Аналитика** → **«Проверка операций приёма-передачи (вся БД)»** (`CommandParameter="All"`)
- **Контекстное меню организации** (ПКМ, вкладка «Формы 1») → **Аналитика** → пункт выбранной org

## Параметры сопоставления

Перед выгрузкой открывается диалог с чекбоксами полей **отдельно для 1.1 и 1.3**. Снятое поле не участвует в решении «парная / непарная» и не подсвечивается.

**Не участвуют в сравнении** (только вывод): рег.№, ОКПО организации, сокращённое наименование, даты периода, № п/п.

## Excel

- Лист **«Легенда»**.
- Листы **«Форма 1.1»** / **«Форма 1.3»**: слева непарная операция, справа после тёмного разделителя — ближайшее совпадение с теми же колонками; **зелёный / жёлтый / красный** по уровню поля; колонка **«Схожесть, %»**.

- Имя файла (org): `{рег}_{ОКПО}_проверка_приёма_передачи`.
- Имя файла (вся БД): `проверка_приёма_передачи_вся_БД`.

### Closest-match (soft-score)

Парность **не** менялась: для пары по-прежнему нужны точные ключи (дата операции, парные коды, паспорт/зав.№ и т.д. по галочкам). Soft-score только выбирает и подсвечивает кандидата справа.

| Сигнал | Роль |
|--------|------|
| Паспорт + зав.№ | Самый сильный вес; полное совпадение обоих (непустых) — бонус |
| Зав.№ `рег/год/номер` ↔ ядро | Почти Exact (жёлтый Near), напр. `74041/22/0436` ↔ `0436` |
| Суффикс года паспорта при **том же ядре** | Near (`3197/25` ↔ `3197/2`); разные ядра при общем годе (`829/22`↔`721/22`) — Mismatch |
| Lookalike в типе/номере | `3C0`=`3СО`=`ЗС0`; `4С0`↔`4СО-534` — Near |
| Радионуклиды | Порядок не важен; отсутствие/лишний нуклид — Mismatch (вес повышен) |
| Опечатка в 1 символ (длина > 2) | Near; 2+ символа — Mismatch |

Цвета: Exact → зелёный, Near → жёлтый, Mismatch → красный. **«Схожесть, %»** — нормированный индекс (не калиброванная вероятность): ≥80 / 50–79 / &lt;50 с той же палитрой. Подробности — лист «Легенда».

## Архитектура (org / вся БД)

Алгоритм парности и closest-match — **одно ядро** (`AnalyzeFormForOrganization` / `ComputeUnpairedOperations` / `BuildClosestMatchResults`): без обращений к БД, только DTO. Каждая включённая форма вызывает его со своими `TransferReceiveFormParams` и отдельным пулом ops.

Формы подключены через **реестр** `ImplementedFormDescriptors` (`Forms.cs`): discover / bulk / org-load / Excel / closest идут циклом по включённым формам (`EnabledForms`), а не через жёсткую пару `enable11`/`enable13`.

| Режим | Отличие |
|-------|---------|
| Выбранная org | Точечная загрузка своих ops по включённым формам + контрагентов по ОКПО кол. 19 (пакеты по 20 org); своя org в пул не перечитывается |
| Вся БД | Discover (Distinct Id + титулы form_10) → bulk: **один scan** на форму → ОКПО-карта из титулов (+ хвост `LoadRepsIdsByOkpo`) → **один** shared `opsByOrgOkpo` на форму → цикл unpaired/closest/Excel (`GetNextDataRow`, «Организация i из N») |

Копия temp DB не оптимизируется (общая для выгрузок, доля времени мала).

### Как добавить форму (напр. 1.2)

1. `TransferReceiveFormId.Form12` + строка в `ImplementedFormDescriptors` (SheetName, UsesAggregateStateColumn / будущий layout-флаг).
2. Слот в `TransferReceiveParamsSet` + чекбоксы диалога.
3. Ветки в диспетчерах: `AddRepsIdsForFormAsync`, `LoadFormOpsForRepsAsync` / `…ForRepsIdsAsync`, `LoadAllFormOpsAsync`.
4. При отличии колонок/soft: отдельный DTO или layout writer (сейчас ИИИ-layout общий для 1.1/1.3).
5. Тесты + легенда.

### Techdebt / отложено

- **Вариант B discover+bulk:** один проход по form_11/13 сразу даёт и candidates, и ops (сейчас A: отдельный Distinct + full-scan ops, как Pairing41). Имеет смысл после замеров на большой БД.
- SQL/OKPO loader integration-тесты.
- Формы **1.2, 1.4, 1.5–1.8** — отдельными запросами (инфраструктура multi-form уже готова; правила полей 1.2 — следующим шагом).
- Коды **26↔36**: парные, но **только для форм 1.5–1.8**; в load-set 1.1/1.3 их нет намеренно. В общей таблице `TransferToReceiveCode` пара уже есть — подключатся при реализации 1.5–1.8.

### Smoke вручную

- Выбранная org с известными парами 21↔31 → пустой или ожидаемый Excel.
- Вся БД: несколько org с непарными → один файл, строки append без перезаписи; progress «Организация i из N»; bulk-этапы «форма 1.1 / 1.3».
- Снятие Check* в диалоге (секции 1.1 / 1.3) меняет состав непарных; **все поля формы выкл.** → форма не грузится и не пишется в Excel.
- Дата ±1 день → строка в отчёте, дата **жёлтая** у closest (окно ±15).
- Soft: зав.№ с префиксом рег./года, УКТ-варианты, активность на порядок — жёлтый; колонка «Схожесть, %».
- Форма 1.3: разное агрегатное состояние → непарная; снятие CheckAggregateState → пара.
