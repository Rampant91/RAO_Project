# Проверка операций приёма-передачи

## Назначение

Функция находит операции передачи и приёма, для которых не нашлась парная операция у контрагента, и выгружает их в Excel.

**Текущая реализация:** формы **1.1** и **1.3**, режимы **выбранная организация** и **вся БД**. Листы 1.2, 1.4–1.8 создаются пустыми (зарезервированы). Сверка только same-form (1.1↔1.1, 1.3↔1.3).

## Где вызывается

- **Аналитика** → **Выбранная организация** → **«Проверка операций приёма-передачи»**
- **Аналитика** → **«Проверка операций приёма-передачи (вся БД)»** (`CommandParameter="All"`)
- **Контекстное меню организации** (ПКМ, вкладка «Формы 1») → **Аналитика** → пункт выбранной org

## Параметры сопоставления

Перед выгрузкой открывается диалог с чекбоксами полей **отдельно для 1.1 и 1.3**. Снятое поле не участвует в решении «парная / непарная» и не подсвечивается.

**Не участвуют в сравнении** (только вывод): рег.№, ОКПО организации, сокращённое наименование, даты периода, № п/п.

## Логика сверки

| Параметр | Форма 1.1 | Форма 1.3 |
|----------|-----------|-----------|
| Коды передачи | 21, 22, 25, 27, 28, 29 | те же |
| Коды приёма | 31, 32, 35, 37, 38, 39 | те же |
| Парность кодов | 21↔31, 22↔32, 25↔37, 27↔35, 28↔38, 29↔39 | те же |
| Коды 26↔36 | Не используются на 1.1/1.3 (ожидаются на формах **1.5–1.8**) | — |
| Дата операции | Точное совпадение для пары/подсветки; окно поиска кандидатов ±15 дней | то же |
| Суммарная активность | ±10% | то же |
| Количество | сравнивается | всегда 1 (не сравнивается) |
| Агрегатное состояние | нет | ключ пары + closest (1/2/3) |
| Пустые серии | суммирование qty | всегда 1:1 |

Контрагент — по ОКПО в кол. 19.

## Excel

- Лист **«Легенда»**.
- Листы **«Форма 1.1»** / **«Форма 1.3»**: слева непарная операция, справа после тёмного разделителя — ближайшее совпадение с теми же колонками; зелёный/красный по включённым полям.
- На 1.3 колонка «Количество, шт» заменена на **«Агрегатное состояние»**.
- Имя файла (org): `{рег}_{ОКПО}_проверка_приёма_передачи`.
- Имя файла (вся БД): `проверка_приёма_передачи_вся_БД`.

## Архитектура (org / вся БД)

Алгоритм парности и closest-match — **одно ядро** (`AnalyzeForm11ForOrganization` / `ComputeUnpairedForm11` / `BuildClosestMatchResults`): без обращений к БД, только DTO. Формы 1.1 и 1.3 вызывают его с разными `TransferReceive11Params` и отдельными пулами ops.

| Режим | Отличие |
|-------|---------|
| Выбранная org | Точечная загрузка своих ops 1.1+1.3 + контрагентов по ОКПО кол. 19 (пакеты по 50 org); своя org в пул не перечитывается |
| Вся БД | Discover (Distinct Id + титулы form_10) → bulk: **один scan** form_11 и form_13 → ОКПО-карта из титулов (+ хвост `LoadRepsIdsByOkpo`) → **один** shared `opsByOrgOkpo` → цикл unpaired/closest/Excel (`GetNextDataRow`, «Организация i из N») |

Копия temp DB не оптимизируется (общая для выгрузок, доля времени мала).

### Techdebt / отложено

- **Вариант B discover+bulk:** один проход по form_11/13 сразу даёт и candidates, и ops (сейчас A: отдельный Distinct + full-scan ops, как Pairing41). Имеет смысл после замеров на большой БД.
- SQL/OKPO loader integration-тесты.
- Формы **1.2, 1.4, 1.5–1.8** — отдельными запросами.
- Коды **26↔36**: парные, но **только для форм 1.5–1.8**; в load-set 1.1/1.3 их нет намеренно. В общей таблице `TransferToReceiveCode` пара уже есть — подключатся при реализации 1.5–1.8.

### Smoke вручную

- Выбранная org с известными парами 21↔31 → пустой или ожидаемый Excel.
- Вся БД: несколько org с непарными → один файл, строки append без перезаписи; progress «Организация i из N»; bulk-этапы «форма 1.1 / 1.3».
- Снятие Check* в диалоге (секции 1.1 / 1.3) меняет состав непарных.
- Дата ±1 день → строка в отчёте, дата красная у closest.
- Форма 1.3: разное агрегатное состояние → непарная; снятие CheckAggregateState → пара.
