# Проверка парности операций при переводе РВ → РАО (код операции 41)

## Назначение

В программе предусмотрен перевод сведений о **радиоактивных веществах (РВ)** в сведения о **радиоактивных отходах (РАО)** по **коду операции 41**. Перевод выполняется из форм учёта РВ в соответствующие формы учёта РАО. На практике часть источников после перевода «теряется»: запись есть только в форме РВ или только в форме РАО, либо данные в парных строках не сходятся.

**Функция поиска непарных строк** автоматически находит такие расхождения и выгружает их в Excel. Это помогает:

- выявить **потерянные при переводе** источники и операции;
- понять, **где именно** осталась «лишняя» или **отсутствующая** запись;
- опираясь на даты операций и документов в выгрузке, **восстановить хронологию передвижения** источников между формами и отчётными периодами;
- провести сверку **по одной организации** или **по всей базе данных** (в зависимости от выбранного режима запуска).

Функция **не заменяет** кнопку перевода по коду 41 и **не исправляет** данные сама — она даёт наглядный отчёт для ручного анализа и доработки отчётности.

---

## Связь форм РВ и РАО

Перевод по коду 41 в системе устроен так:

| Форма РВ (источник) | Форма РАО (приёмник) | Содержание |
|---------------------|----------------------|------------|
| **1.1** — ЗРИ | **1.5** — РАО в виде отработавших ЗРИ | закрытые источники |
| **1.2** — изделия из обеднённого урана | **1.6** — некондиционированные РАО | ИОУ |
| **1.3** — ОРИ (отдельные изделия) | **1.6** | открытые источники — изделия |
| **1.4** — ОРИ (прочие) | **1.6** | открытые источники — иные учётные единицы |

Проверка парности строится на сопоставлении строк с кодом **41** между **парой форм** из одной строки таблицы: для каждой пары ищутся записи на стороне РВ, для которых нет эквивалента на стороне РАО, и наоборот.

> **Планируемый охват кнопок:** отдельные команды (или пункты меню) для пар **1.1↔1.5**, **1.2↔1.6**, **1.3↔1.6**, **1.4↔1.6** — всего шесть форм, четыре направления сравнения.  
> **Текущая реализация в программе:** выгрузка непарных операций 41 для пары **форм 1.1 и 1.5** по выбранной организации (см. раздел «Где вызывается»).

---

## Где вызывается

- **Аналитика → Выбранная организация** — команды выгрузки и проверок по текущей организации (вкладки «Формы 1» / «Формы 2»).
- **Контекстное меню организации** (ПКМ по строке в списке организаций) — пункт **«Аналитика»** с тем же набором действий для выбранной организации.
- **По всей БД** — запуск из раздела аналитики без привязки к одной организации (режим предусмотрен задачей; объём данных больше, время выполнения дольше).

Для работы по организации нужно, чтобы в списке была **выбрана** нужная организация.

---

## Как работает проверка (общая логика)

### 1. Отбор операций

Из базы (или её временной копии для выгрузки) выбираются **все строки с кодом операции 41** в проверяемых формах за выбранный объём:

- только **одна организация**, либо  
- **все организации** в базе.

На первом этапе из базы читаются **только поля, нужные для сравнения** (а не полная строка формы). Это ускоряет работу при больших объёмах данных.

### 2. Сопоставление «парная / непарная»

Две записи считаются **парными**, если совпадают **ключевые реквизиты** операции:

1. код операции (41);  
2. дата операции;  
3. номер паспорта (сертификата);  
4. тип;  
5. радионуклиды;  
6. заводской номер;  
7. дата выпуска;  
8. вид документа;  
9. номер документа;  
10. дата документа;  
11. номер упаковки (УКТ).

Сравнение выполняется с **нормализацией** значений (как в других аналитических функциях по СНК): игнорируются лишние пробелы, разный регистр, типичные обозначения «нет номера» (прочерк, «б/н», «без номера» и т.п.), для радионуклидов — порядок и написание в списке, для дат — приведение к одному формату.

**Особый случай — пустые паспорт и заводской номер.**  
Если оба поля пустые или содержат только «условно пустые» значения, пользователи часто вносят одну и ту же партию источников по-разному:

- одна строка с **количеством 8**, или  
- **восемь строк** с **количеством 1** каждая.

При совпадении остальных ключевых полей такие варианты считаются **одной партией**: сравнивается **суммарное количество** по группе строк на форме РВ и на форме РАО. Если суммы равны, партия считается полностью переведённой; в отчёт попадает только **нераспределённый остаток** (лишние единицы на одной из сторон).

Если **паспорт или заводской номер заполнены**, сопоставление идёт **построчно** с учётом количества в каждой строке.

### 3. Результат

- Строки формы РВ **без пары** на форме РАО попадают в выгрузку как непарные на стороне РВ.  
- Строки формы РАО **без пары** на форме РВ — как непарные на стороне РАО.  
- Если непарных записей нет, программа сообщает об этом и файл не формирует (или формирует пустой отчёт — в зависимости от версии).

### 4. Выгрузка в Excel

Для каждой непарной строки подгружаются **полные данные** формы (второй этап — только по найденным идентификаторам строк, без лишней нагрузки на базу).

Файл **.xlsx** содержит:

- отдельные листы по проверяемым формам (например, «Форма 1.1» и «Форма 1.5»);
- реквизиты организации и отчётного периода;
- поля операции и паспортные/документные данные в привычном для аналитики виде;
- оформление в виде таблицы Excel (фильтр, чередование строк).

Имя файла для организации обычно включает **рег. №**, **ОКПО** и пометку о непарных операциях 41; при совпадении имени добавляется суффикс `_1`, `_2` и т.д.

## Чем помогает на практике

| Задача | Как помогает функция |
|--------|----------------------|
| Найти источник, перевели ли его в РАО | Непарная строка на 1.1 (или 1.2–1.4) показывает, что в 1.5/1.6 пары нет |
| Найти «лишнюю» запись в РАО | Непарная строка на 1.5/1.6 без соответствия в РВ |
| Понять массовый перевод без номеров | Сопоставление по сумме количества снижает ложные «непарные» при 8×1 и 1×8 |
| Сверить организацию перед сдачей | Режим «выбранная организация» |
| Региональная / полная сверка | Режим «вся БД» |
| Восстановить хронологию | В выгрузке видны даты операции, выпуска и документов по всем непарным движениям — удобно выстраивать последовательность вручную или вместе с другими отчётами |

После исправления данных в отчётах имеет смысл **повторно** запустить проверку или выполнить штатный **перевод по коду 41** для оставшихся строк.

---

## Рекомендации пользователю

1. Перед проверкой убедитесь, что по организации завершён ввод операций 41 в формах РВ и выполнен перевод там, где он требуется.  
2. Для организаций с большим числом операций 41 предпочтительнее сначала проверка **по одной организации**, затем — свод по БД.  
3. Непарная строка — повод открыть соответствующий отчёт в программе и сравнить с парной формой, а не автоматический признак ошибки ввода (возможны особые случаи учёта).  
4. При пустых паспорте и заводском номере сверяйте **суммарное количество** по группе одинаковых реквизитов, а не только число строк.

## Техническая справка (кратко)

| Элемент | Описание |
|---------|----------|
| Команда (1.1 / 1.5, организация) | `ExcelExportCheckPairingOfCode41AsyncCommand` |
| Сравнение ключей | `Operation41PairingKeyComparer`, `Operation41PairingMatcher` |
| Перевод РВ → РАО | отдельные команды перевода по коду 41 в контекстном меню строк форм 1.1–1.4 |

При расширении на формы **1.2–1.4 ↔ 1.6** сохраняется та же схема: узкая загрузка ключевых полей → сопоставление → полная выгрузка только непарных строк → листы Excel по соответствующим формам.
