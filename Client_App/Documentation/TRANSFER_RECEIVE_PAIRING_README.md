# Проверка операций приёма-передачи

## Назначение

Функция находит у **выбранной организации** операции передачи и приёма, для которых не нашлась парная операция у контрагента, и выгружает их в Excel.

**Текущая реализация:** формы **1.1** и **1.3**, режим **выбранной организации**. Листы 1.2, 1.4–1.8 создаются пустыми (зарезервированы). Сверка только same-form (1.1↔1.1, 1.3↔1.3).

## Где вызывается

- **Аналитика** → **Выбранная организация** → **«Проверка операций приёма-передачи»**
- **Контекстное меню организации** (ПКМ, вкладка «Формы 1») → **Аналитика** → тот же пункт

## Параметры сопоставления

Перед выгрузкой открывается диалог с чекбоксами полей **отдельно для 1.1 и 1.3**. Снятое поле не участвует в решении «парная / непарная» и не подсвечивается.

**Не участвуют в сравнении** (только вывод): рег.№, ОКПО организации, сокращённое наименование, даты периода, № п/п.

## Логика сверки

| Параметр | Форма 1.1 | Форма 1.3 |
|----------|-----------|-----------|
| Коды передачи | 21, 22, 25, 27, 28, 29 | те же |
| Коды приёма | 31, 32, 35, 37, 38, 39 | те же |
| Парность кодов | 21↔31, 22↔32, 25↔37, 26↔36, 27↔35, 28↔38, 29↔39 | те же |
| Дата операции | Точное совпадение для пары/подсветки; окно поиска кандидатов ±15 дней | то же |
| Суммарная активность | ±10% | то же |
| Количество | сравнивается | всегда 1 (не сравнивается) |
| Агрегатное состояние | нет | ключ пары + closest (1/2/3) |
| Пустые серии | суммирование qty | всегда 1:1 |

Контрагент — по ОКПО в кол. 19.

## Excel

- Лист **«Легенда»**.
- Листы **«Форма 1.1»** / **«Форма 1.3»**: слева непарная операция, справа после тёмного разделителя — ближайшее совпадение с теми же колонками; зелёный/красный по включённым полям.
- На 1.3 колонка «Количество, шт» заменена на **«Агрегатное состояние»**.
- Имя файла: `{рег}_{ОКПО}_проверка_приёма_передачи`.

## Архитектура (org / будущая вся БД)

Алгоритм парности и closest-match — **одно ядро** (`AnalyzeForm11ForOrganization` / `ComputeUnpairedForm11` / `BuildClosestMatchResults`): без обращений к БД, только DTO. Формы 1.1 и 1.3 вызывают его с разными `TransferReceive11Params` и отдельными пулами ops.

| Режим | Отличие |
|-------|---------|
| Выбранная org | Точечная загрузка своих ops 1.1+1.3 + контрагентов по ОКПО кол. 19; своя org в пул не перечитывается |
| Вся БД (план) | Один bulk-load ops/титулов, затем то же ядро по каждой org in-memory |

Копия temp DB не оптимизируется (общая для выгрузок, доля времени мала).

### Smoke вручную

- Выбранная org с известными парами 21↔31 → пустой или ожидаемый Excel.
- Снятие Check* в диалоге (секции 1.1 / 1.3) меняет состав непарных.
- Дата ±1 день → строка в отчёте, дата красная у closest.
- Форма 1.3: разное агрегатное состояние → непарная; снятие CheckAggregateState → пара.
